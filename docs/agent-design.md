# Human Epochs 学习 Agent 概要设计

Human Epochs 是面向 Web 和 App 的通用学习 Agent。一次学习请求可以从问题、原文或活动开始。用户可以要求解释、核对出处、补充材料，也可以进入活动继续讨论和领取提示。系统采用模块化单体，客户端共用服务端和 PostgreSQL。会话接续以服务端记录为准。

## 核心运行模型

**请求执行内核。** 学习者每提交一条消息，服务端以稳定的请求 ID 收件。应用服务为一次尝试组装当前问题、相关对话、材料和可用能力。内核可以直接回答，也可以在同一次尝试内调用工具取得材料，再让模型根据结果组织回复。所有执行步骤共用当次尝试的期限和调用预算，最终发布一条回复。Web 和 App 通过相同的请求与恢复接口接入。

**多轮会话与模型输入。** 学习者可以连续追问。每次请求从当前消息分支、已选材料和允许的历史重新构建模型输入。跨端恢复读取已收件的消息、已发布回复及其引文。页面离开或断线后可以继续读取回复。学习者也可以在任一设备显式停止正在生成的回复，原消息仍留在对话中。重试沿用原请求，从保存的输入重新执行。晚到的回复只有在它仍属于当前有效尝试时才能发布。

**教学能力与学习记录。** 教学策略依据当前问题和可读材料选择讲解、澄清或工具。本地工具由服务端注册，按当前请求校验参数、可读来源和返回内容。课程提供讨论问题、材料和提示。开始活动和领取提示由显式命令执行。活动内问答和已领提示支持跨端回看。

系统分为接入层、应用层、核心层和基础设施层。核心层中的执行内核负责一次运行，学习领域负责课程、活动和提示。分层依赖、模块接口、请求生命周期和实施顺序见[架构设计](architecture.md)。模型接口与运行依赖见[技术选型](technology-choices.md)。

Web 提供管理员运行设置，可直接填写 OpenAI 兼容服务的 Base URL、API Key 和模型 ID，分区调整生成、上下文和执行预算。设置助手可以解释参数、追问需求并提出模型 ID 和运行参数的修改草案。管理员填入并保存后，新的请求尝试使用更新后的设置。[运行参数契约](architecture.md#运行设置)

## 材料与呈现

材料讨论接受用户自带的原文。模型回复中的引文须能在本轮可读的指定原文中逐字找到。模型不可用或引文核验失败时，应用服务可以发布有来源的课程导读或原文摘录。

AI 根据学习者的问题和所选材料决定每轮回复的内容类型、呈现形式和阅读顺序。遇到简单问题可以直接答一句，需要解释交互顺序时可以先展示时序图，接着说明关键事件。客户端根据设备采用等价视图，例如在手机上把桌面的时序图呈现为事件列表。

会话保存已发布的内容和来源引用。内容契约、存储、跨端呈现及实施顺序见[学习内容呈现技术设计](content-presentation.md)。

## 数字自我与授权

数字生命是长期目标。会话摘要帮助 Agent 接续同一会话，可以从有效会话记录重新生成。跨会话使用的个人记录区分本人陈述、Agent 推断和个人愿望，各自保留来源、适用情境、有效时间和允许用途。学习者可以回看出处、纠正、忘记或撤回用途授权。纠正和删除使依赖旧来源的摘要与学情推断失效。 [记忆系统设计](memory-design.md)

代办授权单独记录动作、对象、期限和数量，执行时再次核对授权，并按操作 ID 去重。

## 当前实现

Web 已提供多轮文字对话、Markdown 正文、消息重试、跨端续读和历史引文。未使用记忆的普通在线对话随模型生成逐步显示。服务端支持材料讨论、练习接续、活动问答、提示和讨论历史读取。较长的材料讨论可以在一次请求内按需读取原文，引文核验后再展示回复。在线对话支持按需摘要。Web 的「个人记忆」支持查看来源、纠正、授权和忘记。 [记忆系统设计](memory-design.md)
