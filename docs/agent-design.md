# Human Epochs 学习 Agent 概要设计

Human Epochs 是面向 Web 和 App 的通用学习 Agent。用户可以直接在对话里提问、带入原文或继续讨论。AI 根据当前意图和已有学习记录，组织讲解、练习与复习。用户也可以核对引文来源、补充材料和领取提示。系统采用模块化单体，客户端共用服务端和 PostgreSQL。对话接续以服务端记录为准。

## 核心运行模型

**请求执行内核。** 用户每提交一条消息，服务端以稳定的请求 ID 收件。应用服务为一次尝试组装当前问题、相关对话、材料和可用能力。内核可以直接回答，也可以在同一次尝试内调用工具读取原文，再让模型根据结果组织回复。所有执行步骤共用当次尝试的期限和调用预算，最终发布一条回复。Web 和 App 通过相同的请求与恢复接口接入。

**多轮对话与模型输入。** 用户可以按学习主题开多个对话，在每个对话里连续追问，各对话的历史互不混入。每次请求从当前消息分支、已选材料和允许的历史重新构建模型输入。跨端恢复读取已收件的消息、已发布回复及其引文。页面离开或断线后可以继续读取回复。用户也可以在任一设备显式停止正在生成的回复，原消息仍留在对话中。重试沿用原请求，从保存的输入重新执行。晚到的回复只有在它仍属于当前有效尝试时才能发布。

**教学能力与学习记录。** 教学策略依据当前问题和可读材料选择讲解、澄清或工具。本地工具由服务端注册，按当前请求校验参数、可读来源和返回内容。课程提供讨论问题、材料和提示。开始活动和领取提示由显式命令执行。活动内问答和已领提示支持跨端回看。

系统分为接入层、应用层、核心层和基础设施层。核心层中的执行内核负责一次运行，学习领域负责课程、活动和复习。分层依赖、模块接口、请求生命周期和实施顺序见[架构设计](architecture.md)。模型接口与运行依赖见[技术选型](technology-choices.md)。

Web 提供管理员运行设置，可直接填写 OpenAI 兼容服务的 Base URL、API Key 和模型 ID，分区调整生成、上下文和执行预算。设置助手可以解释参数、追问需求并提出模型 ID 和运行参数的修改草案。管理员填入并保存后，新的请求尝试使用更新后的设置。[运行参数契约](architecture.md#运行设置)

## 材料与呈现

材料讨论接受用户自带的原文。用户在输入框旁「附加原文」，粘贴文字或读取 .txt、.md、.pdf、.docx 文件（文件只在浏览器里转成文字，原件不上传），随下一条消息发出；PDF 按页标注页码。一份原文和一场讨论最多 50 万字，原文只存一次，Agent 按需搜索和分段读取。附加过的原文保存在「我的材料」里，可以在其他对话里直接选用，相同内容不会重复保存；删除材料会清除它的全文，以及依据它写出的回复和复习，对话和用户的消息保留；超出上限时可以选择页码范围；之后在同一对话里的提问自动接着这份材料讨论，讨论中可以再补充原文，也可以结束讨论回到普通对话。模型回复中的引文须能在本轮可读的指定原文中逐字找到。模型不可用或引文核验失败时，应用服务可以发布有来源的课程导读或原文摘录。

AI 根据用户的问题和所选材料决定每轮回复的内容类型、呈现形式和阅读顺序。遇到简单问题可以直接答一句，需要解释交互顺序时可以先展示时序图，接着说明关键事件。客户端根据设备采用等价视图，例如在手机上把桌面的时序图呈现为事件列表。

对话保存已发布的内容和来源引用。内容契约、存储、跨端呈现及实施顺序见[学习内容呈现技术设计](content-presentation.md)。

## 主动复习

AI 根据来源可核对的学习记录判断值得复习什么、什么时候再问，以及用什么问题检验理解。用户回到对话时，Agent 可以发出复习邀请。例如「上次我们聊到怎么区分亲历和转述。要不要换个例子试试？」用户可以接受邀请、稍后再答、继续聊别的，或让 Agent 停止主动提醒。

用户像平时一样回复。AI 先让用户尝试回忆，再根据答案和原文反馈，判断这个问题是否值得以后再问。复习适用于课程材料和用户自己附加的原文，复习题和反馈都以讨论时的原文为依据。从隔一段时间后能否独立答出一道换过的题观察效果。[复习架构](architecture.md#主动复习) 每次作答的结果分为独立答出、部分答出和没想起来，并附一句依据；结果决定下次复习的远近。用户可以在「学习记录」里查看每个复习主题的作答历史和下次复习时间，停止复习某个主题，或在停止全部提醒后重新开启。

## 学习目标

用户可以设定想长期学会的事作为学习目标，写下为什么想学和目前学到哪里，并随时暂停、完成或删除。在对话中说出想学的东西时，Agent 可以提议设为目标，用户确认后才保存。进行中的目标会作为背景交给 Agent，让讲解和建议联系到用户想达成的事。[学习目标](architecture.md#学习目标)

## 数字自我与授权

数字生命是长期目标。对话摘要帮助 Agent 接续同一对话，可以从有效对话记录重新生成。跨对话使用的个人记录区分本人陈述、Agent 推断和个人愿望，各自保留来源、适用情境、有效时间和允许用途。用户可以在原对话中记住所说的内容，并就地查看来源消息、纠正、忘记或撤回授权。用户开启记忆提议后，Agent 可以从用户消息中提出值得记住的内容，并附上理由和原话依据，用户确认后才保存，拒绝过的内容不再提议。纠正和删除使依赖旧来源的摘要与学情推断失效。 [记忆系统设计](memory-design.md)

代办授权单独记录动作、对象、期限和数量，执行时再次核对授权，并按操作 ID 去重。

## 当前实现

用户可以在登录页自行注册（部署方可以关闭注册），注册后通过邮件确认邮箱；忘记密码时可以通过邮件里的链接设置新密码。在「账号设置」里可以改名字和密码，改密码后其他设备上的登录会退出；可以下载自己的全部数据；删除账号会删除对话、材料、记忆和复习记录，无法恢复。用户可以按关键词搜索自己的对话，直接打开匹配的那一轮。

Web 已提供多个对话（新建、按最近使用列出、切换、重命名和删除，每个对话有自己的地址；删除对话不删除从中保存的记忆）、多轮文字对话、Markdown 正文、消息重试、跨端续读和历史引文。未使用记忆的普通在线对话随模型生成逐步显示。服务端支持材料讨论、活动接续、活动内问答、提示领取和讨论历史读取。较长的材料讨论可以在一次请求内按需读取原文，引文核验后再展示回复。讲解多方交互时，回复可以包含事件记录，桌面显示为时序图，手机上显示为事件列表。讲解步骤、条件或因果时，回复可以包含流程与关系图，手机上显示为关系列表。普通对话也可以出现这两种图示，因为没有原文可核对，图下注明由 AI 整理、未核对来源。在线对话支持按需摘要，用户可以在对话消息旁管理记忆，保存的记忆会在其他对话里遇到相关问题时用上，回复下方注明参考了哪些记忆，也可以开启记忆提议并逐条确认或拒绝。 [记忆系统设计](memory-design.md)

在线模式下可以在对话中讨论课程发布的材料，由 AI 提议复习内容和时机。到期的复习邀请、复习题和反馈支持跨端接续。[主动复习](#主动复习)
