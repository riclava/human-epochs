# Human Epochs 首版技术选型

首版使用 TypeScript、Node.js LTS、Fastify、React、PostgreSQL 和 Zod。服务端采用模块化单体。各端通过同一应用服务使用学习对话、课程和活动。目标模块与交付顺序见[架构设计](architecture.md)。

| 技术 | 用途 |
| --- | --- |
| TypeScript 与 Node.js LTS | 服务端、Web 和测试共享契约。请求执行使用普通异步函数，模型通过依赖注入接入。 |
| Fastify | 处理登录态、HTTP 校验和公开响应。生产构建后由服务端提供 Web 静态资源。 |
| React 与 Vite | 手机和桌面共用对话页面。Vite 开发服务器通过本地代理调用 API。 |
| PostgreSQL | 保存登录会话、对话记录、材料快照、活动和提示收据。用事务、行锁和条件更新实现收件、尝试发布与并发写入。 |
| Zod | 校验服务端请求、课程内容和结构化回复。工具接入后也使用 Zod 校验调用参数与结果。 |
| OpenAI 兼容接口 | 适配器根据管理员保存的连接和模型 ID 调用 Chat Completions。基址和凭据由服务端建立绑定。本地学习引导通过同一应用路径返回回复。 |

## 模型适配与交付范围

服务端部署环境提供默认连接、加密密钥和管理员名单。Web 管理员可覆盖 Base URL、API Key 和模型 ID。连接、加密后的凭据和运行参数保存在 PostgreSQL，每次在线模型尝试读取同一份配置。OpenAI 官方地址使用 `max_completion_tokens`，其他兼容地址使用 `max_tokens`。长材料工具与设置助手要求所选模型支持相应的工具调用与 JSON 响应。参数范围和保存冲突规则见[运行设置](architecture.md#运行设置)。

DeepSeek 的 Chat Completions 单次输出可配置到 393,216 Token，应用以此作为 DeepSeek 档案的默认请求上限。上下文窗口为 1M Token。执行仍受应用超时和总期限约束。[DeepSeek 接口文档](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/) · [模型详情](https://api-docs.deepseek.com/quick_start/pricing/)

对话应用服务通过统一的请求执行接口处理一条用户消息，模型输入包含预算内和本次对话授权范围内的前文。普通在线对话的 Chat Completions 请求使用 `stream: true`。适配器转发 `delta.content`，收到 `stop` 和 `[DONE]` 后完成本次生成。材料讲解和设置助手使用完整的结构化响应。长材料讨论在同一次尝试内编排模型与工具调用，通过 `tool_calls` 和 `tool_call_id` 配对。截断或中断进入当前用例的重试或回退路径。规则引导用于本地运行和确定性测试。

服务端和 Web 使用 `eventsource-parser` 读取 SSE。服务端持久化请求状态和已发布回复，客户端中断时通过同一个只读快照接口恢复。Web 使用 `react-markdown` 将生成中的正文和已发布正文转成 React 元素。

## 内容存储选型

存储方式由数据的读取粒度、保存期限和访问范围决定。当前对话按用户和消息顺序读取，活动按 ID 读取并独立更新。AI 可以用同一份源数据生成文字、表格或图表，源数据的存储归属由应用服务决定。

| 数据 | 存储选择 | 选择依据 |
| --- | --- | --- |
| 用户输入、收件状态及材料快照 | 原消息使用 PostgreSQL `text`，请求 ID、身份、顺序和状态使用关系列。本轮所选材料的原文与来源随 `material_context` JSONB 保存。 | 收件状态按请求查询和更新。所选材料随本轮整体读取，保留当时可用的原文，供重试和引用复核。 |
| 已发布的回复和复习题面 | 对话行的 `reply_blocks` 和 `question_blocks` 以 JSONB 保存有序内容块。正文和代码保存原始文本，流程图保存节点与边，引文保留来源引用。 | 客户端按回复或题面整体回读，各块字段因类型而异。内容和完成状态在同一事务中提交。 |
| 课程题面和材料 | 复用 `course_versions` 的 JSONB 内容，活动保存所用的课程版本 ID。 | 课程材料按版本整体读取，多个活动可共用同一份题面。 |
| 表格、数值图表和事件记录 | 小型表格、图表和事件记录使用内容块内的结构化数据。需要服务端分页、筛选或按时间范围读取时，将数据放入 PostgreSQL 独立关系表，按数据集和查询字段建索引。内容块引用已发布的数据集 ID。 | 表格和图表可以共用一份数值数据。整组回读适合内联，按行或时间范围读取需要独立查询。 |
| 活动和提示 | `activities` 保存用户归属、课程版本、标题、演示去重键和修订，提示收据另存关系表。 | 两端共用活动详情，并发领取提示由事务和唯一约束协调。 |
| 图片、文档、音频和视频原件 | 文件保存在 RustFS 私有存储桶，服务端通过 S3 兼容接口读写。PostgreSQL 关系表保存资源 ID、存储键、类型、大小与访问归属。发布内容保存资源 ID，授权时生成预签名读取地址。 | 原件按文件读取、下载或分段播放。对话快照读取元数据，访问权限由服务端根据资源记录核对。 |

首轮内容块与现有课程事件都可用 PostgreSQL 交付。课程需要文件原件或媒体时接入 RustFS，出现独立分页或筛选需求时按数据集建表。服务端用 Zod 校验内容，Web 通过共享 TypeScript 契约读取它，再由 React 渲染。具体类型、实施阶段及验收条件见[学习内容呈现技术设计](content-presentation.md)。

对话摘要和个人记忆使用 PostgreSQL。结构化正文可用 JSONB，归属、用途授权、来源依赖和后台任务领取使用关系表。首轮按问题与适用主题匹配召回个人记录，后续按实际召回效果评估语义检索。 [记忆系统设计](memory-design.md)

## 验证

`npm run check` 运行类型检查、契约测试和 PostgreSQL 接口测试。`npm run test:e2e` 用 Chromium 验证登录、窄屏与桌面续读、消息重试和材料引文。两套集成测试使用独立数据库。启动、构建与模型配置见[启动说明](../README.md)。
