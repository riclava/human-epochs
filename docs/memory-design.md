# Human Epochs 记忆系统设计

记忆系统服务两种读取。同一会话用可重建的摘要接续被裁剪的前文，学习者授权的个人记录帮助 Agent 在其他会话延续学习目标、偏好和已确认的选择。跨端回看继续使用 PostgreSQL 中已经收件和发布的记录。首版已接通在线对话摘要和显式个人记忆。个人记忆按学习者授权用于普通在线学习辅导，摘要也适用于材料分支。

## 设计原则

| 主题 | 设计 |
| --- | --- |
| 会话重建 | 普通对话按收件顺序重建，材料讨论沿 `parentRequestId` 回溯。两端读同一份公开记录，摘要只进入本次模型输入。 |
| 摘要生成 | 从已发布轮次推导有明确覆盖边界的摘要。领取任务、标记完成和核对来源由 PostgreSQL 协调，生成在事务外执行。 |
| 个人记忆召回 | 先按学习者、用途、情境和时效取得可用候选，再按相关性读取少量正文。每次尝试使用当前权限重新读取。 |
| 个人记忆写入 | 首版支持显式保存。以后如需自动提取，发布后可以生成待确认候选，后台整理与学习者确认的写入分别执行。 |

## 数据归属与用途

| 数据 | 所有者与用途 | 存储 |
| --- | --- | --- |
| 原始对话、材料和活动 | 对话、课程、活动各自保存权威记录。通过各领域入口校验学习者、原文和活动归属。近期历史及 UI 回看读这些记录。 | 复用 `chat_turns`、课程材料和活动表。 |
| 会话摘要 | 对话应用层为一次会话范围保存可重建的上下文。普通对话按收件位置确定范围，材料讨论按当前叶节点的父链确定范围。 | `conversation_summaries` 保存学习者、范围、覆盖起止请求、结构化摘要、来源修订和可用状态。 |
| 个人记忆 | 个人记忆领域保存本人陈述、Agent 推断、个人愿望。每条记录保留内容、来源、适用情境、有效期、允许用途和修订号。学员可回看、纠正、撤销用途或忘记。 | `personal_memories` 保存当前记录及状态。当前的学习辅导授权与来源消息保存在记录中，`memory_command_receipts` 保存去重所需的标识。 |

首版摘要保存来源请求 ID，并从已发布轮次中的学员原话逐字验证引句。个人记忆可关联一条来源消息。回复使用的个人记录保存在 `chat_memory_sources`，按学习者和记忆 ID 反查依赖。

源记录的修订用于核对内容和权限。学习者维度的 `memory_revision` 在纠正、删除、撤权等可能使已有输入失效的操作中递增，供正在执行的任务检查。三类数据沿用同一套 PostgreSQL 和单一初始化迁移。 [技术选型](technology-choices.md)

## 会话摘要

1. **确定覆盖范围。** `loadContext` 先读取当前获准的材料范围，再按当前问题和近期完整轮次计算剩余历史预算。历史字节预算或轮次窗口裁掉可用前文时，在回复发布事务中登记摘要任务。任务以学习者、会话范围、覆盖边界和来源修订去重。普通对话只选当前请求之前的轮次，材料摘要的覆盖段必须位于当前父链，兄弟分支只能复用共同前缀的摘要。
2. **生成摘要。** 后台任务以期限和尝试序号领取，使用单独的模型预算和可注入的生成器，在事务外从有上限的原始记录生成摘要。从学员原话择取学习目标、已讨论结论和未决问题，每条引句必须逐字匹配指定来源消息。首版生成器只读取学员原话。提炼和重建都从有效原始记录出发，摘要存储实际覆盖边界。摘要超出单次生成预算时只覆盖能完整读入的轮次，保留可追溯的覆盖范围。
3. **发布摘要。** 应用服务在同一次事务中复查任务领取、来源修订和当前可用范围，写入结果并完成任务。崩溃后其他进程可领取到期任务，迟到结果须匹配当前尝试与来源状态。相同覆盖边界与来源修订只发布一份结果，读取时选择当前父链或普通会话中最近的有效覆盖边界。
4. **还原模型输入。** 从历史预算中为有效摘要划出有上限的空间，余量用于近期完整轮次和当前问题。摘要结束边界必须早于保留的近期轮次，预算允许时补入两者间的完整轮次。无可用摘要、任务积压或生成失败时，使用现有历史裁剪回答。后续持久化工具结果时，调用与结果作为同一组保留。回复引文继续核对获准的原文。

摘要任务首轮复用 PostgreSQL。任务行保存输入范围、领取期限与结果状态，通过行锁领取，以短事务提交。同一覆盖边界和来源修订以任务主键去重。固定的时钟、生成器和 ID 用于验证进程退出、重试和迟到结果。普通问题继续使用现有请求预算，摘要任务单独限时、限次。

## 个人记忆

### 写入与管理

- Web 侧栏提供「个人记忆」，已完成的学员消息可作为保存来源。`GET /api/memories` 读取当前记录，`GET /api/memories/source/:id` 回看本人原话，`POST /api/memories` 受理 `remember`、`correct` 和 `forget`。写入时校验本人身份、来源、当前修订及允许用途。稳定操作 ID 用于重试，先读收据，再校验新命令。重放返回收据及当前公开视图。纠正生成新修订，忘记清除记录正文并留下识别重放所需的标识。
- 个人记忆可直接来自学员的保存命令，也可指向学员选中的对话来源。已确认的推断仍保留推断类型与依据。材料里的他人陈述、模型解释和练习中的假设分别留在原有领域。
- 首轮开放学习辅导用途，保存时由学员显式勾选授权。学员可以查看一条记录的出处、有效期及授权范围，并修改授权。忘记命令作用于该条个人记录及其派生内容，原始消息和材料由各自的领域命令处理。
- 后续如需自动提取，从已发布且允许提取的学习者消息生成候选。候选携带类型、理由、原始来源与拟用范围，学员确认后再成为可用记录。忘记或拒绝的来源保留去重标识，避免后台任务重复提交同一候选。整理任务可以发现重复和冲突，并提交供学员处理的建议。

### 按用途读取

`recallMemories` 由教学上下文调用。服务端从登录会话确定学习者，由用例指定用途。先在 PostgreSQL 中按身份、有效期、用途、适用情境和来源可见性筛选，再按当前问题是否包含适用主题匹配并排序。单轮最多尝试纳入四条个人记忆，和摘要共用 6,000 字节上限以及本轮历史预算。召回不足时再评估语义检索。无符合条件的条目时返回空结果，新尝试和跨端接续用当前结果重建视图。

教学规则和当前问题优先。会话摘要、个人记忆和材料分别作为数据组装，个人记录携带类型和来源标识。应用服务在一致的数据库快照内读取记忆修订、可用来源和用途授权，发布前复核。代办由独立授权记录限定动作、对象、期限和数量。 [产品承诺](agent-design.md#数字自我与授权)

## 纠正、删除与并发发布

加载参考记忆的回复记录用到的个人记忆 ID，接续使用历史回复时继承其个人记忆依赖。主题和有效期也适用于这些派生回复的模型回读。普通回读按当前公开权限呈现历史，来源被删除或失去查看权限时，受影响内容以不可用状态呈现。模型历史与摘要生成仅使用本次用途下依赖仍有效的来源。

1. 来源所有者在同一事务里保存纠正或删除、更新来源状态并递增 `memory_revision`。撤销用途更新个人记忆授权并触发同样的核验。个人记忆变更会清除依赖它的回复正文，用同一块 ID 写入不可用状态，并使旧修订下的摘要和任务失效。
2. 摘要与对话发布事务先锁定学习者行，再核对尝试序号、期限、读取时的 `memory_revision` 及当前来源有效性。来源变化时废弃旧摘要任务，下一次需要压缩时从当前来源重新登记。对话尝试仍持有领取权时按剩余次数落为可重试或失败，显式重试重新组装当前输入。读取与发布直接以当前时钟判断有效期。
3. 首轮使用摘要或个人记忆的尝试在服务端缓冲正文，复核并写入数据库后随终态 `turn` 发布。这让执行中的撤权和纠正可以拦截对应正文。收件事件和恢复快照继续遵守现有协议。 [回复发布与恢复](architecture.md#3-对话请求执行与恢复)

## 实施与验收

| 顺序 | 交付 | 验收条件 |
| --- | --- | --- |
| 1. 会话摘要（已落地） | 基于回复内容块和现有历史组装接入来源引用与修订、摘要表和后台领取，并用长会话回放复现当前裁剪损失。 | 保住先前目标和未决问题，同时保留完整尾部。在分支续问、两端重试、模型失败、进程退出和旧任务迟到时，只使用仍有效的摘要或回退到近期历史。 |
| 2. 显式个人记忆（已落地） | 增加领域命令、带出处的公开视图、用途校验和有限召回。接入普通学习辅导。 | 两端读取同一条当前修订。跨学习者、错用途和过期的记录均不进入模型。纠正或忘记后，重放不会恢复旧内容，旧结果无法发布。 |
| 3. 记忆提取候选 | 按需要从获准的对话消息提取候选，接入本人确认。再根据试用决定是否做整理与语义检索。 | 旧提取任务迟到、候选重复和学员拒绝后重建均按当前来源处理。 |

用固定模型捕获实际输入，验证预算、来源与用途授权。用 PostgreSQL 测并发纠正、过期任务和命令重放，用 Chromium 测两台设备上的管理、续读与空结果替换。记录摘要生成耗时、选中条数、预算和失效原因，日志省略内容与凭据。
