# Human Epochs 记忆系统设计

记忆系统服务两种读取。同一对话用可重建的摘要接续被裁剪的前文，用户授权的个人记录帮助 Agent 在其他对话延续学习目标、偏好和已确认的选择。跨端回看继续使用 PostgreSQL 中已经收件和发布的记录。已接通在线对话摘要、显式个人记忆和需本人确认的记忆提议。个人记忆按用户授权用于普通在线学习辅导，摘要也适用于材料讨论分支。

## 设计原则

| 主题 | 设计 |
| --- | --- |
| 对话重建 | 普通对话在所属对话内按收件顺序重建，材料讨论沿 `parentRequestId` 回溯。两端读同一份公开记录，摘要只进入本次模型输入。 |
| 摘要生成 | 从已发布轮次推导有明确覆盖边界的摘要。领取任务、标记完成和核对来源由 PostgreSQL 协调，生成在事务外执行。 |
| 个人记忆召回 | 先按用户、用途和时效取得可用候选，再按与当前问题的字面相关程度选出少量正文，跨对话可用。每次尝试使用当前权限重新读取。 |
| 个人记忆写入 | 支持显式保存和记忆提议。本人开启提议后，回复发布时登记提取任务，后台生成待确认候选，用户确认的写入走个人记忆命令。 |

## 数据归属与用途

| 数据 | 所有者与用途 | 存储 |
| --- | --- | --- |
| 原始对话、材料和活动 | 对话、课程、活动各自保存权威记录。通过各领域入口校验用户身份、材料的可见范围和活动归属。近期历史及 UI 回看读这些记录。 | 复用 `conversation_turns`、课程材料和活动表。 |
| 对话摘要 | 对话应用层按对话范围保存可重建的上下文。普通对话按收件位置确定范围，材料讨论按当前叶节点的父链确定范围。 | `conversation_summaries` 保存覆盖边界 `boundary_request_id`、来源请求 `source_request_ids`、记忆修订 `memory_revision`、结构化摘要和可用状态。 |
| 个人记忆 | 个人记忆领域保存本人陈述、Agent 推断、个人愿望。每条记录保留内容、来源、适用情境、有效期、允许用途和修订号。用户可回看、纠正、撤销用途或忘记。 | `personal_memories` 保存当前记录及状态。当前的学习辅导授权与来源消息保存在记录中，`personal_memory_command_receipts` 保存去重所需的标识。 |
| 记忆提议 | 个人记忆领域保存待本人确认的候选。候选只来自本人开启提议后发布的消息，携带类型、理由、逐字依据、来源消息和拟用范围。 | `users.memory_suggestions_enabled` 保存提议开关，`personal_memory_extractions` 保存提取任务，`personal_memory_candidates` 保存候选及去重指纹。 |

摘要条目和个人记忆均通过 `sourceRequestId` 引用来源消息。摘要引文从已发布轮次中的 `messageText` 逐字验证。回复使用的个人记录保存在 `conversation_memory_sources`，按用户和记忆 ID 反查依赖。

源记录的修订用于核对内容和权限。`users.memory_revision` 在纠正、删除、撤权等可能使已有输入失效的操作中递增，供正在执行的任务检查。三类数据沿用同一套 PostgreSQL 和单一初始化迁移。 [技术选型](technology-choices.md)

## 对话摘要

1. **确定覆盖范围。** `loadContext` 先读取当前获准的材料范围，再按当前问题和近期完整轮次计算剩余历史预算。历史字节预算或轮次窗口裁掉可用前文时，在回复发布事务中登记摘要任务。任务以用户、对话范围、覆盖边界和来源修订去重。普通对话只选当前请求之前的轮次，材料摘要的覆盖段必须位于当前父链，兄弟分支只能复用共同前缀的摘要。
2. **生成摘要。** 后台任务以期限和尝试序号领取，使用单独的模型预算和可注入的生成器，在事务外从有上限的原始记录生成摘要。从用户原话择取学习目标、已讨论结论和未决问题，每条引文必须逐字匹配指定来源消息。首版生成器只读取用户原话。提炼和重建都从有效原始记录出发，摘要存储实际覆盖边界。摘要超出单次生成预算时只覆盖能完整读入的轮次，保留可追溯的覆盖范围。
3. **发布摘要。** 应用服务在同一次事务中复查任务领取、来源修订和当前可用范围，写入结果并完成任务。崩溃后其他进程可领取到期任务，迟到结果须匹配当前尝试与来源状态。相同覆盖边界与来源修订只发布一份结果，读取时选择当前父链或普通对话中最近的有效覆盖边界。
4. **还原模型输入。** 从历史预算中为有效摘要划出有上限的空间，余量用于近期完整轮次和当前问题。摘要结束边界必须早于保留的近期轮次，预算允许时补入两者间的完整轮次。无可用摘要、任务积压或生成失败时，使用现有历史裁剪回答。后续持久化工具结果时，调用与结果作为同一组保留。回复引文继续核对获准的原文。

摘要任务首轮复用 PostgreSQL。任务行保存输入范围、领取期限与结果状态，通过行锁领取，以短事务提交。同一覆盖边界和来源修订以任务主键去重。固定的时钟、生成器和 ID 用于验证进程退出、重试和迟到结果。普通问题继续使用现有请求预算，摘要任务单独限时、限次。

## 个人记忆

### 写入与管理

- Web 在已完成的用户消息下提供「记住这条消息」。`GET /api/conversations/:conversationId` 随对话返回当前记忆，已有来源的记录在原消息旁展开，未关联消息的记录在对话中可展开查看。`GET /api/personal-memories` 读取当前记录，`GET /api/personal-memories/source/:sourceRequestId` 返回本人原话 `messageText`。`POST /api/personal-memories` 受理 `remember`、`correct`、`forget` 以及[记忆提议](#记忆提议)的命令，纠正和忘记需要提交 `expectedRevision`。写入时校验本人身份、来源、当前修订及允许用途。收据保存稳定操作 ID 和原始命令指纹。重放先核对指纹，再返回当前公开视图。纠正生成新修订，忘记清除记录正文并保留收据。
- 个人记忆可直接来自用户的保存命令，也可指向用户选中的来源消息。已确认的推断仍保留推断类型与依据。材料里的他人陈述、模型解释和练习中的假设分别留在原有领域。
- 首轮开放学习辅导用途，用户在保存时显式勾选授权。接口通过 `authorizedForTutoring` 读写该授权，数据库保存为 `authorized_for_tutoring`。用户可以查看一条记录的来源、有效期及授权范围，并修改授权。忘记命令作用于该条个人记录及其派生内容，原始消息和材料由各自的领域命令处理。
- 整理任务可以发现重复和冲突，并提交供用户处理的建议。是否开放整理与语义检索，根据记忆提议的试用决定。

### 记忆提议

1. **开启与登记。** 用户在对话顶部的「记忆设置」中开启「让 Agent 从我的消息中提议记忆」，命令为 `set_suggestions`，默认关闭。在线模型可用时，普通对话和材料讨论的回复发布事务会为该条用户消息登记提取任务。复习作答、本地引导回复和开启前的消息不登记。
2. **提取。** 后台任务按尝试序号和期限领取，领取时记下 `users.memory_revision`。生成器在事务外只读取来源消息和已从这条消息保存的记忆，每条消息最多提出三条候选。候选的 `quote` 须逐字出自来源消息，与已保存记忆重复的候选被丢弃。
3. **发布。** 发布事务锁定用户记录后依次复核：提议已关闭时取消任务；记忆修订已变化时释放领取，让下一次尝试读取当前记忆；任务已被其他尝试接手时丢弃结果。候选的去重指纹由来源消息和规范化后的依据组成，同一指纹只保留一行。
4. **确认。** `GET /api/conversations/:conversationId` 和 `GET /api/personal-memories` 返回待处理的 `candidates`、`suggestionsEnabled` 和仍在处理的 `suggestionsPending`，Web 在来源消息旁展示提议。`accept_candidate` 允许用户先修改内容、类型、主题和有效期，学习辅导授权仍由用户勾选。来源消息取自候选本身，新记录沿用候选 ID。`reject_candidate` 拒绝候选。两种命令都使用个人记忆的操作收据。
5. **保留去重标识。** 接受、拒绝或因关闭提议而清除的候选只保留指纹和状态，正文、依据和理由一并清空。重建提取或旧任务迟到时，同一依据不会再次提出。由候选生成的记录被忘记后，指纹仍然保留。

### 按用途读取

`recallPersonalMemories` 由教学上下文调用。服务端从登录会话确定用户，普通对话指定学习辅导用途 `tutoring`。先在 PostgreSQL 中按身份、有效期、用途、适用情境和来源可见性筛选，再由 [`selectMemories`](../src/app/memory-relevance.ts) 按与当前问题的相关程度排序：问题里出现完整主题得分最高，其次是主题与问题共有的词，再次是正文与问题共有的词。西文按整词计，中文按相邻两字计，并去掉「怎么」「可以」这类常见虚词。带主题的记忆只有相关时才使用；不带主题的通用记忆在相关记忆之后补足名额。单轮最多纳入四条个人记忆，和摘要共用 6,000 字节上限以及本轮历史预算。只比较字面，因此「考试」和「考雅思」这样意思相关、字面不同的说法仍会漏掉，需要时再评估语义检索。引用过个人记忆的旧回复进入模型历史时使用同一规则：记忆失效时去掉这条回复，带主题的记忆与当前问题无关时也去掉。无符合条件的条目时返回空结果，新尝试和跨端接续用当前结果重建视图。

Web 在用过个人记忆的回复下方显示「参考了 N 条记忆」，展开后列出这些记忆的正文。对话快照为每条用户轮次带上 `memoryIds`，客户端只显示快照里仍然有效的记忆，忘记或撤权的记忆不再列出。

教学规则和当前问题优先。对话摘要、个人记忆和材料分别作为数据组装，个人记录携带类型和来源标识。应用服务在一致的数据库快照内读取记忆修订、可用来源和用途授权，发布前复核。代办由独立授权记录限定动作、对象、期限和数量。 [产品承诺](agent-design.md#数字自我与授权)

## 纠正、删除与并发发布

加载参考记忆的回复记录用到的个人记忆 ID，接续使用历史回复时继承其个人记忆依赖。主题和有效期也适用于这些派生回复的模型回读。普通回读按当前公开权限呈现历史，来源被删除或失去查看权限时，受影响内容以不可用状态呈现。模型历史与摘要生成仅使用本次用途下依赖仍有效的来源。

1. 来源所有者在同一事务里保存纠正或删除、更新来源状态并递增 `memory_revision`。撤销用途更新个人记忆授权并触发同样的核验。个人记忆变更会清除依赖它的回复正文，用同一块 ID 写入不可用状态，并使旧修订下的摘要和任务失效。
2. 摘要与对话发布事务先锁定对应的用户记录，再核对尝试序号、期限、读取时的 `memory_revision` 及当前来源有效性。来源变化时废弃旧摘要任务，下一次需要压缩时从当前来源重新登记。对话尝试仍持有领取权时按剩余次数落为可重试或失败，显式重试重新组装当前输入。读取与发布直接以当前时钟判断有效期。
3. 首轮使用摘要或个人记忆的尝试在服务端缓冲正文，复核并写入数据库后随终态 `turn` 发布。这让执行中的撤权和纠正可以拦截对应正文。收件事件和恢复快照继续遵守现有协议。 [回复发布与恢复](architecture.md#3-对话请求执行与恢复)

## 实施与验收

| 顺序 | 交付 | 验收条件 |
| --- | --- | --- |
| 1. 对话摘要（已落地） | 基于回复内容块和现有历史组装接入来源引用与修订、摘要表和后台领取，并用长对话回放复现当前裁剪损失。 | 保住先前目标和未决问题，同时保留完整尾部。在分支续问、两端重试、模型失败、进程退出和旧任务迟到时，只使用仍有效的摘要或回退到近期历史。 |
| 2. 显式个人记忆（已落地） | 增加领域命令、标明来源的公开视图、用途校验和有限召回。接入普通学习辅导。 | 两端读取同一条当前修订。跨用户、错用途和过期的记录均不进入模型。纠正或忘记后，重放不会恢复旧内容，旧结果无法发布。 |
| 3. 记忆提取候选（已落地） | 从本人开启提议后的对话消息提取候选，接入本人确认。再根据试用决定是否做整理与语义检索。 | 旧提取任务迟到、候选重复和用户拒绝后重建均按当前来源处理。 |

用固定模型捕获实际输入，验证预算、来源与用途授权。用 PostgreSQL 测并发纠正、过期任务和命令重放，用 Chromium 测两台设备上的管理、续读与空结果替换。记录摘要生成耗时、选中条数、预算和失效原因，日志省略内容与凭据。
