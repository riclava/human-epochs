# 学习内容呈现技术设计

AI 根据学习者的问题和本轮材料，决定用哪些内容、采用什么形式，以及如何组合和排序。一句文字可以直接回答简单问题，解释多方交互时也可以先给时序图再解释。服务端提供本轮可用的类型和呈现形式，校验后保存回复及来源。Web 和 App 按已发布的选择渲染，并根据屏幕和可访问需求采用等价视图。

当前 Web 已展示 Markdown 正文、引文和整组材料，服务端保存课程材料、讨论问题和提示。首轮回复契约已使用正文、原文摘录和段落引用内容块。事件视图、表格、图表、流程图及媒体按具体用例接入。执行与收件流程见[架构设计](architecture.md)，文字、控件和间距沿用[界面设计系统](design-system.md)。

## 内容块契约

学习对话的 `ChatTurn.content` 保存 AI 选出的内容块及其顺序。`complete` 必须包含至少一个内容块，类型可按需要省略或重复。`pending`、`retryable`、`failed` 和 `stopped` 使用 `null`，界面根据状态显示进度、重试入口或停止结果。学习者输入由 `ChatTurn.text` 表示，回复来源使用 `explanationMode`。本地学习引导、课程导读和原文摘录通过各自的规则生成同一结构。

每个已发布块包含 `id`、`kind` 和对应类型的字段。`id` 由服务端分配，在同一回复内唯一，供跨端续读、内部引用和组件更新使用。`kind` 决定数据结构及渲染组件。需要举证的内容可带 `citations`，每项包含来源 `id`、显示名 `label` 和逐字引句 `quote`。服务端从当轮材料快照解析显示名并核对引句。摘录块将该引用保存在 `source` 字段。派生回复失效时使用同 ID 的 `unavailable` 块。

Agent 正文支持 Markdown 标题、段落、列表、强调、引用、代码和 HTTP 或 HTTPS 链接。Web 在生成中和回读时使用同一渲染组件，忽略内嵌 HTML，图片只显示替代文字。学习者原文、材料和来源引句以纯文本呈现。代码作为可选择的等宽文本展示，图表、流程图和媒体由客户端预设组件渲染。

解释和依据可以在同一正文块中发布，组件在段落附近展示来源和引句。

```json
{
  "id": "a35aa85c-d36a-44a9-aa05-843542fb5971",
  "kind": "text",
  "text": "这次观测只给出了上午的气温。",
  "citations": [
    {
      "id": "weather-notes",
      "label": "观测笔记",
      "quote": "九点测得树荫下的气温为二十度。"
    }
  ]
}
```

## 内容类型与呈现

| 类型 | 数据与存储归属 | 可选呈现 | 窄屏与可访问呈现 |
| --- | --- | --- | --- |
| 正文 `text` | 正文和段内引用随回复保存。 | 说明用段落，步骤用有序列表。 | 正文、长链接及标识符可换行。 |
| 代码 `code` | 代码文本和可选语言随回复保存。 | 独立代码块保留原文和缩进。 | 长行在块内滚动，代码可选择和复制。 |
| 原文摘录 `excerpt` | `source` 随回复保存，当轮材料快照保存来源名和原文。 | 相关段落旁展示引句和出处，多段原文可展开。 | 原文在正文流内换行，键盘可展开并读取全文。 |
| 事件记录 `event_log` | 短记录随回复保存事件 ID、参与方、公开顺序或时间及说明，需要按时间范围读取时引用数据集 ID。用 `view` 记录所选形式。 | AI 可选时序图 `sequence`、时间线 `timeline` 或事件列表 `list`。 | 使用同一事件数据生成有序列表，逐步查看控件可通过键盘操作。 |
| 表格 `table`、数值图表 `chart` | 两者共用列 ID、列名、单位和数据行的结构。随回复整组读取时内联保存。需要服务端分页或筛选时引用已发布的数据集 ID。图表另存图型和字段映射，可单独作为一块发布。 | AI 可选择表格呈现精确数值、用折线图呈现趋势或用柱状图比较类别。 | 保留语义表头，宽表在有名称的区域内滚动。图表提供用同一份数据生成的可读表格。 |
| 流程与关系图 `diagram` | 节点 ID、带方向的连线、连线标签及文字说明随回复保存。课程预制图随课程发布。 | 按节点和带标签的连线表达顺序、条件或关系。 | 提供保留步骤和关系的文字视图。提供缩放时，控件支持键盘操作。 |
| 媒体与文档 `media` | 内容块引用资源 ID，可附图注、页码或时间点。PostgreSQL 保存存储键、媒体类型、大小及访问范围，文件正文保存在 RustFS 私有存储桶。 | 图片配图注，文档提供原件入口，音视频由学习者启动播放。 | 图片提供替代文字，音频配文字稿，有语音的视频配字幕。预览不可用时提供有访问权限的原件入口。 |

一份材料可以支持多种视图。时序图和事件列表共用事件 ID 和顺序，图表和表格共用数值及单位，图中关系与文字视图使用相同节点。布局、折叠、图表切换和浏览位置属于客户端状态。

## 存储与发布

`chat_turns.content_blocks` 使用 PostgreSQL JSONB 保存完整的已发布回复。原始消息继续保存在 `message_text`，收件时可用的原文保存在 `material_context`。随回复整组读取的数据内联保存，独立数据集和媒体通过 ID 关联。独立数据集 ID 指向一份固定的数据发布，后续改动生成新的数据集 ID，历史回复仍可读回原数据。架构仍使用一份初始化迁移。各种存储方式的适用条件见[内容存储选型](technology-choices.md#内容存储选型)。

1. 应用服务向执行内核提供本轮可用的内容类型、呈现形式和资源范围。AI 根据学习意图选择内容块、呈现形式和顺序，执行内核使用模型或工具的结果组装候选。材料讲解保留段落和引文的对应关系。
2. 应用服务校验候选的结构、呈现形式与引用。引句须逐字出自本次模型实际读取的指定原文。工具产物引用其获准的输入。图表字段须属于内联数据或引用数据集的列，流程图连线须指向已定义节点。附件在上传并完成校验后才能关联。无效的材料讲解走现有课程导读或原文摘录回退。普通讲解无法形成可发布内容时，沿用当前的可重试或失败状态。
3. 应用服务为全部有效内容块分配 ID，保留选定的类型、呈现形式和顺序。当前尝试仍有效时一次写入完整内容和完成状态。重试已完成的请求直接读取原收据及内容。模型分段与未完成的工具输出只用于当次运行。
4. 读取时，服务端按登录身份和资源归属构造公开视图。媒体读取在启用附件后按当前访问权签发临时地址。引用失效时，公开视图保留该块的位置与不可用状态，省略受限数据。
5. 客户端按块顺序使用对应组件。某块引用的资源无法读取时在原位置显示状态，能够重试时只重新读取该资源。有访问权限的文字和替代视图仍然可读。

## 实施顺序与验收

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| 一、替换回复契约（已落地） | 在共享聊天契约中加入首批 `text`、`excerpt` 和段落引用，在收件表、应用服务、模型讲解及 Web 消息组件一起接入。正文复用 Markdown 渲染组件。 | 单块文字、先摘录后讲解等不同组合按模型选定的顺序回读。已完成请求重试返回同一批 ID 和顺序，错误引文触发已有回退。 |
| 按需接入结构化视图 | 具体学习场景需要时接入相应内容块。每种类型同时交付校验器、组件和文字或数据替代视图。 | 各端视图使用同一份公开数据，错误引用及无效连线被拦截。 |
| 按需接入文档和媒体 | 在课程使用原件或音视频时接入附件元数据、RustFS、授权读取及预览组件。 | 未获授权的账户无法取得私有原件的预签名地址。地址过期后，仍有权限的学习者可以重新获取。音视频支持分段读取，图片替代文字、音频文字稿和视频字幕可用，无法预览的文件有获准的原件入口。 |

契约测试覆盖未知类型、重复块 ID、空完成回复、错误来源和无效图表字段。PostgreSQL 接口测试验证一次提交完整发布、旧尝试结果被拒绝和两端恢复同一公开内容。Web 浏览器测试覆盖桌面、`320px` 窄屏、文字放大至 200%、键盘访问、阅读位置与加载失败恢复。
