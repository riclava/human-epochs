# 学习内容呈现技术设计

AI 根据用户的问题和本轮材料，决定用哪些内容、采用什么形式，以及如何组合和排序。一句文字可以直接回答简单问题，解释多方交互时也可以先给时序图再解释。服务端提供本轮可用的类型和呈现形式，校验后保存回复及来源。Web 和 App 按已发布的选择渲染，并根据屏幕和可访问需求采用等价视图。

当前 Web 已展示 Markdown 正文、引文和整组材料，用户可以在输入框旁附加自己的原文，服务端保存课程材料、讨论问题和提示。回复契约已使用正文、原文摘录、段落引用、事件记录和流程与关系图内容块。表格、图表及媒体按具体用例接入。执行与收件流程见[架构设计](architecture.md)，文字、控件和间距沿用[界面设计系统](design-system.md)。

## 内容块契约

用户轮次的 `messageText` 保存原消息，`replyBlocks` 保存回复内容及其顺序。状态为 `complete` 时至少有一个回复块，类型可按需要省略或重复。状态为 `pending`、`retryable`、`failed` 或 `stopped` 时，`replyBlocks` 为 `null`，界面显示相应的进度、重试入口或停止结果。材料讲解通过 `explanationSource` 标明回复来源。本地学习引导、课程导读和原文摘录通过各自的规则生成同一结构。系统发布的复习题在 `questionBlocks` 中提供题面。

每个已发布块包含 `id`、`kind` 和对应类型的字段。`id` 由服务端分配，在同一轮次内唯一，供跨端续读、内部引用和组件更新使用。`kind` 决定数据结构及渲染组件。需要举证的内容可带 `citations`，每项包含来源 ID `sourceId`、来源名称 `label` 和引文 `quote`。服务端从当轮材料快照取得来源名称，并以对应原文核对引文。摘录块将该引用保存在 `source` 字段。派生内容失效时使用同 ID 的 `unavailable` 块。

Agent 正文支持 Markdown 标题、段落、列表、强调、引用、代码和 HTTP 或 HTTPS 链接。Web 在生成中和回读时使用同一渲染组件，忽略内嵌 HTML，图片只显示替代文字。用户原话、材料原文和引文以纯文本呈现。代码作为可选择的等宽文本展示，图表、流程图和媒体由客户端预设组件渲染。

解释和依据可以在同一正文块中发布，组件在段落附近展示来源和引文。

```json
{
  "id": "a35aa85c-d36a-44a9-aa05-843542fb5971",
  "kind": "text",
  "text": "这次观测只给出了上午的气温。",
  "citations": [
    {
      "sourceId": "weather-notes",
      "label": "观测笔记",
      "quote": "九点测得树荫下的气温为二十度。"
    }
  ]
}
```

## 内容类型与呈现

| 类型 | 数据与存储归属 | 可选呈现 | 窄屏与可访问呈现 |
| --- | --- | --- | --- |
| 正文 `text` | 正文和段内引用随回复保存。 | 说明用段落，步骤用有序列表。 | 正文、长链接及标识符可换行。 |
| 代码 `code` | 代码文本和可选语言随回复保存。 | 独立代码块保留代码文本和缩进。 | 长行在块内滚动，代码可选择和复制。 |
| 原文摘录 `excerpt` | `source` 随回复保存，当轮材料快照保存来源名称和原文。 | 相关段落旁展示引文和来源，多段原文可展开。 | 原文在正文流内换行，键盘可展开并读取全文。 |
| 事件记录 `event_log` | 短记录随回复保存标题、参与方、事件 ID、公开顺序及说明，需要按时间范围读取时引用数据集 ID。用 `view` 记录所选形式。 | AI 可选时序图 `sequence` 或事件列表 `list`，时间线 `timeline` 按需要接入。 | 使用同一事件数据生成有序列表。以后加入逐步查看控件时，控件须支持键盘操作。 |
| 表格 `table`、数值图表 `chart` | 两者共用列 ID、列名、单位和数据行的结构。随回复整组读取时内联保存。需要服务端分页或筛选时引用已发布的数据集 ID。图表另存图型和字段映射，可单独作为一块发布。 | AI 可选择表格呈现精确数值、用折线图呈现趋势或用柱状图比较类别。 | 保留语义表头，宽表在有名称的区域内滚动。图表提供用同一份数据生成的可读表格。 |
| 流程与关系图 `diagram` | 标题、节点 ID 与名称、带方向的连线及连线标签随回复保存。课程预制图随课程发布。 | 按节点和带标签的连线表达顺序、条件或关系，闭合循环的连线画在右侧。 | 提供保留全部连线和孤立节点的关系列表。以后提供缩放时，控件须支持键盘操作。 |
| 媒体与文档 `media` | 内容块引用资源 ID，可附图注、页码或时间点。PostgreSQL 保存存储键、媒体类型、大小及访问范围，文件正文保存在 RustFS 私有存储桶。 | 图片配图注，文档提供原件入口，音视频由用户启动播放。 | 图片提供替代文字，音频配文字稿，有语音的视频配字幕。预览不可用时提供有访问权限的原件入口。 |

一份材料可以支持多种视图。时序图和事件列表共用事件 ID 和顺序，图表和表格共用数值及单位，图中关系与文字视图使用相同节点。布局、折叠、图表切换和浏览位置属于客户端状态。

### 事件记录

材料讲解可以发布事件块，用来说明几方之间按先后发生的交互。块内包含标题 `title`、呈现形式 `view`、最多 6 个参与方 `participants`、最多 16 个按公开顺序排列的事件 `events`，以及至少一条逐字引文 `citations`。每个事件有块内 ID、发起方 `from` 和说明 `text`。涉及另一方时填写接收方 `to`，只涉及一方时省略。

- **校验。** 共享契约的 `eventLogProblem` 拦截重复的参与方或事件 ID，以及指向未定义参与方的事件。材料讲解按正文块的规则核对引文和标题、事件说明里的引号内容。模型把引文写在单个事件上时，引文先合并到块上再逐字核对。任一事件块无效时，整条回复走课程导读或原文摘录回退。
- **呈现。** Web 用同一个有序列表承载两种形式。`sequence` 在消息宽度足够时排成时序图：参与方在顶部，每个参与方一条生命线，箭头连接两条生命线，单方事件用虚线框标在本方生命线上。宽度不足、文字放大或选了 `list` 时显示为事件列表，每项先写参与方，再写说明。读屏始终按列表顺序朗读参与方和说明。
- **历史与摘要。** `conversationContentText` 把事件块转成标题加编号的「参与方 → 参与方：说明」行，供后续追问的模型历史使用。

### 流程与关系图

材料讲解可以发布关系图块，用来说明步骤、条件或因果关系。块内包含标题 `title`、2 至 12 个节点 `nodes`、1 至 20 条有方向的连线 `edges`，以及至少一条逐字引文 `citations`。节点有块内 ID 和不超过 24 个字的名称，连线有 `from`、`to` 和可选的、不超过 16 个字的标签 `label`。连线顺序就是关系列表的阅读顺序。

- **校验。** 共享契约的 `diagramProblem` 拦截重复的节点 ID、指向未定义节点的连线、指向自身的连线，以及同一对节点之间的重复连线。材料讲解核对引文，以及标题、节点名称和连线标签里的引号内容。写在节点或连线上的引文先合并到块上再逐字核对。无效时整条回复走已有回退。
- **布局。** Web 的 [`layoutDiagram`](../clients/web/src/diagram-layout.ts) 按节点顺序做深度优先搜索，把闭合循环的连线标为回连，其余连线按最长路径分层。跨越多层的连线在每个中间层占一个占位点，从节点旁边经过。同层顺序先按给定顺序，再用上下层位置的平均值调整，最后只在能严格减少交叉时交换相邻节点，所以给定顺序已经最好时保持不变。回连从源节点下方的层间通道出发，绕到图的右侧，再从目标节点上方的通道进入，不横穿任何一行节点。连线标签放在所属连线的第一段上，先试中点，再试线上的其他几个位置，避开节点、其他标签和其他连线的横段与竖段，都被占用时才横向移开；回连标签纵向错开。节点每行放满节点内宽，左右各留 12px。Web 用页面字体在画布上测量文字宽度，字体加载完成后重新排版；无法测量时按估算处理，汉字和全角字符算一个字宽，西文字符算 0.6 个字宽。换行时西文单词和数字保持完整，比一整行还长的单词才在字母之间断开，汉字可以在任意字之间断行。
- **呈现。** 消息宽度足够时按原始尺寸显示图形，图形对读屏隐藏。图形比消息宽时在一个有名称、可聚焦的区域内横向滚动，页面本身不横向滚动；放得下时这个区域不占用 Tab 焦点。旁边始终保留一份关系列表，按连线顺序列出「节点 → 节点（标签）」，再列出没有连线的节点。宽度不足或文字放大时只显示这份列表，读屏始终朗读它。高对比度模式下图形改用系统颜色。
- **历史与摘要。** `conversationContentText` 把关系图转成标题加关系列表，供后续追问的模型历史使用。

### 普通对话中的图示

没有选材料的普通对话也可以发布事件记录和关系图。模型照常流式输出 Markdown，需要图示时在正文里插入一段代码块，第一行是 ```` ```event_log ```` 或 ```` ```diagram ````，内容是去掉 `kind` 的块 JSON，结尾是单独一行 ```` ``` ````。

- **拆分与校验。** 回复结束后，[`splitConversationReply`](../src/runtime/conversation-blocks.ts) 按这类代码块的位置把回复切成正文块和结构块，结构块用共享契约校验。普通对话没有原文，模型写的引文会被丢弃，结构块不带 `citations`。无效的代码块留在正文里，按普通代码显示，回复不会因此失败。每条回复最多保留三个结构块。
- **流式预览。** 生成过程中，Web 把已开始的图示代码块显示为「正在整理图示…」，不显示原始 JSON。回复发布后由校验过的块替换预览。
- **来源提示。** 不带引文的事件记录和关系图在下方注明「由 AI 整理，未核对来源」，和材料讨论里带逐字引文的图示区分开。

## 存储与发布

`conversation_turns.reply_blocks` 和 `conversation_turns.question_blocks` 使用 PostgreSQL JSONB 分别保存已发布的回复和复习题面。用户原话保存在 `message_text`，提交时选择的材料保存在 `material_selection`，`material_context` 保存收件时获准的材料快照，包括来源和原文。随回复整组读取的数据内联保存，独立数据集和媒体通过 ID 关联。独立数据集 ID 指向一份固定的数据发布，后续改动生成新的数据集 ID，历史回复仍可读回原数据。架构使用一份初始化迁移。各种存储方式的适用条件见[内容存储选型](technology-choices.md#内容存储选型)。

1. 应用服务向执行内核提供本轮可用的内容类型、呈现形式和资源范围。AI 根据学习意图选择内容块、呈现形式和顺序，执行内核使用模型或工具的结果组装候选。材料讲解保留段落和引文的对应关系。
2. 应用服务校验候选的结构、呈现形式与引用。引文须逐字出自本次模型实际读取的指定原文。工具产物引用其获准的输入。图表字段须属于内联数据或引用数据集的列，流程图连线须指向已定义节点。附件在上传并完成校验后才能关联。无效的材料讲解走现有课程导读或原文摘录回退。普通讲解无法形成可发布内容时，沿用当前的可重试或失败状态。
3. 应用服务为全部有效内容块分配 ID，保留选定的类型、呈现形式和顺序。当前尝试仍有效时一次写入完整内容和完成状态。重试已完成的请求直接读取原收据及内容。模型分段与未完成的工具输出只用于当次运行。
4. 读取时，服务端按登录身份和资源归属构造公开视图。媒体读取在启用附件后按当前访问权签发临时地址。引用失效时，公开视图保留该块的位置与不可用状态，省略受限数据。
5. 客户端按块顺序使用对应组件。某块引用的资源无法读取时在原位置显示状态，能够重试时只重新读取该资源。有访问权限的文字和替代视图仍然可读。

## 实施顺序与验收

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| 一、替换回复契约（已落地） | 在共享对话契约中加入首批 `text`、`excerpt` 和段落引用，在收件表、应用服务、模型讲解及 Web 消息组件一起接入。正文复用 Markdown 渲染组件。 | 单块文字、先摘录后讲解等不同组合按模型选定的顺序回读。已完成请求重试返回同一批 ID 和顺序，错误引文触发已有回退。 |
| 二、事件记录（已落地） | 在共享契约、材料讲解、提示词和 Web 消息组件中接入 `event_log`，支持 `sequence` 和 `list` 两种形式。 | 两端读回同一批块 ID、事件和顺序。未定义的参与方、重复 ID、未知形式和无出处的引文触发已有回退。桌面显示时序图，`320px` 窄屏和文字放大至 200% 时显示同一份事件列表，页面不横向滚动。 |
| 三、流程与关系图（已落地） | 在共享契约、材料讲解、提示词和 Web 消息组件中接入 `diagram`，客户端按层次布局绘制。 | 未定义的节点、指向自身或重复的连线、无出处的引文触发已有回退。桌面显示图形，跨层连线不穿过节点，标签互不重叠，过宽的图形在区域内横向滚动。`320px` 窄屏和文字放大至 200% 时显示同一份关系列表，追问时模型历史读到同样的关系。 |
| 四、普通对话中的图示（已落地） | 普通对话用约定的代码块输出事件记录和关系图，发布时拆分校验，生成中显示占位。 | 有效的图示发布为结构块并跨端读回，无效的图示保留为代码文字，不带引文的图示注明未核对来源，追问时模型历史读到同样的文字。 |
| 按需接入其他结构化视图 | 具体学习场景需要时接入表格、图表和时间线。每种类型同时交付校验器、组件和文字或数据替代视图。 | 各端视图使用同一份公开数据，错误引用及无效连线被拦截。 |
| 按需接入文档和媒体 | 用户附加的 PDF 和 Word 已在浏览器里转成文字原文接入，不保存原件。在需要保留原件、预览或音视频时再接入附件元数据、RustFS、授权读取及预览组件。 | 未获授权的用户无法取得私有原件的预签名地址。地址过期后，仍有权限的用户可以重新获取。音视频支持分段读取，图片替代文字、音频文字稿和视频字幕可用，无法预览的文件有获准的原件入口。 |

契约测试覆盖未知类型、重复块 ID、空完成回复、错误来源和无效图表字段。PostgreSQL 接口测试验证一次提交完整发布、旧尝试结果被拒绝和两端恢复同一公开内容。Web 浏览器测试覆盖桌面、`320px` 窄屏、文字放大至 200%、键盘访问、阅读位置与加载失败恢复。
